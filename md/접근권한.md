# 저장소 공개 범위와 팀원 쓰기 권한

2026-11-25 사용자는 **공개 전환 + 지정 팀원에게 쓰기 권한**을 선택했다. 이전의 비공개 유지 선택을 이 요청으로 갱신한다. 소유자는 개인 계정 `kminjae2104`, 기본 브랜치는 `main`이다. 저장소 이전은 하지 않는다.

실제로 적용·재조회한 결과는 [설정 기록](협업/설정변경_20261125.md)을 확인한다. 이름별 실험 폴더를 만든 것과 GitHub 접근 권한은 별개다. [팀원명단](협업/팀원명단.md)의 GitHub 아이디는 나중에 제공될 예정이므로 계정을 추측해서 초대하지 않는다.

## 권한 구분

| 대상 | 가능한 일 |
| --- | --- |
| 누구나(공개 전환 완료 후) | 코드·기록·Git 이력 조회, 복제·fork |
| 지정 팀원(초대 수락 후 collaborator) | 본인 브랜치 push, PR 제출, 권한 범위 내 검토 |
| 소유자 | 설정 변경, 초대, 관리 작업 |

공개는 링크를 아는 팀원에게만 한정된 공개가 아니다. 누구나 접근 가능하다. 공개 저장소라고 모든 사람에게 쓰기가 허용되는 것은 아니다. 개인 저장소의 collaborator는 쓰기도 가능하다. main의 PR 보호와 저장소 전체 권한은 별개다.

## 관리자가 팀원 아이디를 받은 뒤

1. 본인 계정으로 저장소 `Settings → Collaborators → Add people`을 연다.
2. 팀원이 전달한 **정확한 GitHub 아이디**를 확인해 초대한다. 이메일/한글 이름으로 다른 계정을 추정하지 않는다.
3. 초대 전송과 수락을 따로 기록한다. 팀원이 초대를 수락해야 원본 저장소에 push할 수 있다.
4. 실제 collaborator 목록과 권한을 재확인하고 팀원명단을 갱신한다. 초대 중이면 `초대 발송 / 수락 대기`로 적는다.
5. 첫 실험은 `exp/...` 브랜치에 push → PR로 제출한다. main 보호를 풀어서 해결하지 않는다.

아이디 등록 전에는 공개 fork에서 PR을 보낼 수 있다. 팀원의 계정 로그인·서버 권한·라이선스는 공유하지 않는다.

## 협업 설정

main에는 PR, 승인 1명, 코드 소유자 검토, 미해결 대화 해소를 요구하고 강제 push·삭제를 막는 구성을 적용한다. 관리자는 기존 운영과 긴급 유지보수를 위해 예외를 보유한다. 코드 소유자는 `.github/CODEOWNERS`의 `@kminjae2104`다. 관리자의 자기 PR은 직접 승인할 수 없으므로 다른 검토자 또는 관리자 예외를 사용하고 사유를 남긴다.

`gaa-agent-rendezvous`는 통신 주소 발견용이며 팀원 실험을 올리는 브랜치가 아니다. 공개 전환 후에는 **주소·프로토콜·일련번호·서명**이 공개될 수 있다. 비밀키와 접속 토큰은 저장소 밖에 남기고, 중계 API는 인증을 계속 요구한다. 기존 private 전제의 게시 코드는 명시적 공개 호환 설정으로 전환한다. 현재 통신 확인의 범위는 설정 기록에 적는다.
