# 기한 없는 통신 운용과 재등록

2026-11-20 사용자 요청으로 기존 24시간 제한을 제거했다. `control.py start --seconds 0`이 기본이며 중계의 종료 timer가 없고 session의 deadline_utc는 null이다. agent bootstrap도 max_session_seconds와 deadline_utc를 null로 전달한다. 절전 방지와 HTTPS 감시도 같은 무기한 설정을 따른다. TLS·토큰 인증·SHA 검증은 유지한다.

Windows 중계와 학교 서버 전원/네트워크, 임시 tunnel 제공자의 가용성에 의존한다. 예정 만료가 없어도 주소 소실이나 프로세스 중단이 자동으로 해결되는 영구 접점은 아니다. 현재는 `stop.request`, 중계 프로세스 종료, OS/외부 서비스 장애가 있을 때 종료된다. 로컬·원격 양쪽을 종료하려면 먼저 control의 request-stop으로 agent의 명시적 종료를 확인한 뒤 close로 중계를 닫는다.

## 새 agent 등록

runtime: `C:\Users\MinjaeKwak\AppData\Local\TCAD_PRIVATE\gaa_background_20261120T055207Z`

1. runtime의 bootstrap_ca_verified.txt 명령을 MobaXterm 기존 Linux 셸에서 한 번 실행한다. 원격 Python의 CA 저장소 오류를 보완하기 위해 실제 검증된 HTTPS 체인의 공개 루트 인증서를 포함했다. TLS 검증을 끄지 않는다. 기존 bootstrap.txt는 최초 시도 기록이다.
2. Task token (hidden): 입력에는 같은 폴더 token.txt 내용을 입력한다. 토큰은 채팅이나 Git으로 보내지 않는다.
3. AGENT_STARTED만으로 접속 성공을 판단하지 않는다. Windows에서 `py -3.11 python/automation/control.py status`의 live_agent와 heartbeat 시각, 실제 결과 회수를 확인한다.

등록된 agent가 없거나 이전 주소가 사라졌다면 새 주소를 원격으로 전달할 경로가 없으므로 위 1회 등록이 필요하다. PC 화면·키보드·마우스·클립보드를 자동 조작하지 않는다.

## 자동 확인과 분석

`prepare_status_recovery.py`가 기존 3개 GAA 실행 ID만 읽는 snapshot을 미리 큐에 넣고 감시한다. 새 TCAD 계산은 제출하지 않는다. `presentation_connection_guard.py`가 30초 HTTPS/heartbeat 확인과 10분 회수, ZIP/파일 해시 확인, `audit_results.py` 재계산을 수행한다. 원본 덱·로그·구조를 변경하지 않는다.

분석 결과는 `검증/자동총분석_<snapshot ID>/`에 새로 기록한다. 현재 감시 상태는 runtime의 presentation_guard.json, 최신 분석은 latest_audit.json, 원격 수집 요약은 `.local/presentation_guard_latest.json`에서 확인한다. 통신 확인 시각과 원격 snapshot 시각을 구분한다.

23개 자동화 시험을 통과했다. 무기한 중계에 미래 clock을 적용한 인증 요청과 무인증 거부, agent 명시적 중지 등을 포함한다. 이것은 실제 원격 계산 완료나 물리 검증의 증명이 아니다.
