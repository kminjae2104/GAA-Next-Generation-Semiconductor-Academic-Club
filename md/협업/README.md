# GAA 팀원 시작 안내

각자 TCAD를 실행하고 **입력 덱 + 실행 조건 + 실제 결과 + 검증 상태**를 함께 공유한다. 처음에는 아래 순서대로 한 번 따라 하면 된다.

1. [팀원 명단](팀원명단.md)에서 본인 폴더를 확인한다. GitHub 아이디는 관리자에게 별도로 전달한다.
2. [VS Code와 AI로 시작](VSCode와_AI.md) 또는 [AI 없이 시작](AI없이_GitHub.md)을 고른다.
3. [실험 공유 규칙](실험공유규칙.md)에 따라 새 실행 ID를 만들고 사전 계획부터 작성한다.
4. 본인 브랜치에 올리고 Pull Request(PR: main에 반영해 달라는 검토 요청)를 만든다.
5. 검토자가 조건·단위·근거를 확인하고 main에 반영한다. 실패 결과도 원인을 적어 공유한다.

먼저 [폴더별 저장 위치](폴더별_저장위치.md)에서 개인/공통 공간과 문헌/실험의 위치를 확인한다. TCAD를 아직 실행하지 않아도 개인 `문헌/`에 읽기 기록을 올릴 수 있다.

## 꼭 구별할 것

| 말 | 뜻 |
| --- | --- |
| Git / GitHub | PC에서 변경 이력을 관리하는 도구 / 그 이력을 팀과 공유하는 서비스 |
| Clone | 기존 GitHub 저장소를 내 PC로 처음 복제 |
| Branch | 다른 사람과 독립적으로 작업하는 변경 이력 |
| Stage | 다음 커밋에 넣을 파일과 변경을 선택 |
| Commit | 선택한 변경을 **내 PC 이력**에 기록 |
| Push | 내 커밋을 **GitHub**에 업로드 |
| Pull | GitHub의 변경을 내 PC로 가져와 반영 |
| PR / Merge | 반영 검토 요청 / 검토한 변경을 main에 합치기 |

파일 저장, 커밋, push, PR 생성, main 반영은 서로 다른 단계다. GitHub에서 **브랜치 이름과 파일**을 직접 확인해야 공유 여부를 알 수 있다.

## 공개·권한의 의미

2026-11-25 **공개 전환을 완료**했다. 지정 팀원의 쓰기 권한은 GitHub 아이디를 받은 뒤 초대할 예정이다. 실제 설정 확인은 [설정 기록](설정변경_20261125.md)을 따른다. 공개 저장소는 팀원이 아닌 사람도 읽고 복제할 수 있다. 공개 전환만으로 다른 사람에게 쓰기 권한이 생기지는 않는다. 초대 수락 전에는 fork에서 작업해 PR을 제출할 수 있다.

GitHub 권한은 Silvaco 라이선스나 Linux 서버 계정을 제공하지 않는다. 각자의 허가된 실행 환경을 사용한다. 공동 서버에서는 실행 소유자와 동시 실행 수를 먼저 조율한다. 기존 개인 자동화의 최대 3개 제한을 팀원마다 별도로 적용해 서버 전체에 과다 제출하지 않는다.
