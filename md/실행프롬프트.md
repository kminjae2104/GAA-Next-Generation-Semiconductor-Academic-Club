# GAA 개인 연구 저장소 구축 및 첫 Id–Vg 실행 프롬프트

작성일: 2026-11-16 (Asia/Seoul). 아래 지시를 저장한 후 순서대로 실행한다.

## 목적과 범위

`kminjae2104/GAA-Next-Generation-Semiconductor-Academic-Club`에서 개인 GAA 연구를 관리한다. Git·VS Code·Codex로 입력과 분석을 관리하고, Google 원격 데스크톱으로 접속한 Silvaco DevEdit 3D/ATLAS에서 실제 3차원 GAA nMOS를 제작하고 Id–Vg를 계산한다. 초기 기준 소자를 검증한 후 셀 치수 변화 연구로 확장한다.

## 먼저 확인할 사항

1. 현재 작업 저장소의 브랜치·미커밋 변경·README·AGENTS.md·폴더 구조를 읽는다. 다른 STOB 연구와 기존 원시 덱/로그를 보존한다. GAA는 별도 저장소/작업 경로에서 작업한다.
2. GitHub 인증 사용자가 `kminjae2104`인지, 대상 저장소의 공개 범위·기본 브랜치·내용·쓰기 권한을 확인한다. 이메일만으로 인증을 단정하지 않는다.
3. 원격 PC의 접속 대상, DevEdit 3D 및 ATLAS 버전과 라이선스를 확인한다. 비밀번호/PIN은 문서·Git에 남기지 않고 사용자가 직접 입력한다. 다른 작업의 실행을 종료하거나 재개하지 않는다.
4. 특정 부원만 읽기 전용인지, 공개 조회도 허용되는지 묻는다. GitHub 개인 저장소와 조직 저장소의 역할 차이를 공식 문서로 확인한다. 답변 없이 공개 범위 변경, 저장소 이전, 부원 초대를 수행하지 않는다.

## 폴더와 관리

기존 구조가 있으면 따른다. 비어 있으면 루트에 README와 설정·작업 규칙을 두고, `md/`, `문헌/`, `연구/01_GAA_IdVg/{md,tcad,python,검증,그림}`, `연구/02_치수변화/` 등 주제·단계에 맞는 최소 구조를 만든다. 빈 폴더만 두지 말고 설명 파일을 넣는다. 실행 중인 원시 결과는 실행 ID별로 보존하고 대용량 자료는 Git 제외 규칙과 해시 목록으로 관리한다. README에 읽는 순서, 실제 실행 명령, 결과 상태와 주요 링크를 적는다. 첫 기준 소자를 검증하기 전에 대규모 치수 sweep을 시작하지 않는다.

## 문헌 조사와 사전 목표 설정

1. Silvaco 공식 매뉴얼·공식 예제·공식 기술 자료에서 DevEdit 3D의 영역/전극/도핑/단면/3차원 메시/구조 저장과 ATLAS 3D의 구조 로딩·모델·접촉·바이어스·로그 문법을 확인한다. 버전 의존성을 기록한다.
2. 원 논문/저자 원문에서 재현 가능한 GAA 소자 구조를 선택한다. 길이·채널 단면·산화막·일함수·도핑·접촉·온도·바이어스·양자 보정 적용 여부와 근거를 표로 기록한다. 먼저 단일 Si GAA nMOS 기준 소자를 만든다. 문헌 값을 바꿀 때는 이유와 영향, 정확한 재현이 아닌 점을 적는다.
3. Id–Vg의 적절성은 선형/로그 곡선, Ion·Ioff·Ion/Ioff·정의가 고정된 Vth·SS·DIBL·게이트 누설·단자 전류 보존·메시 수렴으로 판단한다. 전류는 A/device와 유효 게이트 둘레 기준 A/um를 구분한다. 문헌과 같은 Vds/Vgs/온도/정규화에서만 수치를 비교한다.
4. 결과를 보기 전에 1차 합격 기준과 문헌상 성능 참고 범위를 정하고 버전 관리한다. 목표 미달을 숨기거나 데이터를 합성하지 않는다. 문헌 목표와 수치해석 건전성 기준을 구분한다. 핵심 참조 문헌에 제목·저자·연도·DOI/URL·참조 위치·차용한 수치를 표기한다.

## 제작과 실제 실행 순서

1. 버전과 라이선스 및 공식 최소 예제 실행으로 환경을 확인한다. 기존 작업과 겹치지 않는 원격 실행 디렉터리와 실행 ID를 만든다.
2. DevEdit 3D로 소스–채널–드레인과 채널의 네 면 또는 전 둘레를 감싸는 절연막/게이트를 만든다. 3차원 절단면에서 단면·전극·소스/드레인 도통·게이트 절연·메시 품질을 검사하고 구조를 저장한다. 2D 또는 축대칭 결과를 3D 결과로 표시하지 않는다.
3. ATLAS 3D에서 구조를 로딩하고 평형 → 작은 Vds → 짧은 Vgs smoke sweep을 실행한다. 실제 stdout/stderr/라이선스/return code/종료 표시/요구 산출물을 검사한다.
4. 저 Vds와 동작 Vds에서 Vgs sweep을 수행한다. 단위·전류 부호·전극 이름·중복/누락 바이어스·NaN·수렴 오류를 확인하고 CSV와 선형/로그 그래프를 만든다.
5. 오류/이상 곡선이면 구문 → 구조/접촉 → 도핑/모델 → 메시 → 바이어스 간격·해법 순으로 원인을 구분하여 수정한다. 시도마다 변경점·오류·가설·결과·소요 시간과 원시 덱/로그의 해시를 보존한다. 기존 실행 산출물을 덮어쓰지 않는다.
6. 정해 둔 목표와 메시 수렴/바이어스 간격 민감도를 통과할 때까지 원인에 근거해 반복한다. 라이선스·접속·사용자 입력이 필요한 문제는 실패 상태와 재개 명령을 남기고 알린다. 같은 실패를 근거 없이 무한 반복하거나 목표를 결과에 맞춰 완화하지 않는다.

## 검증과 전달

문서/링크/실행 경로와 분석 코드의 의미 있는 검증을 수행한다. 로컬 정적 검증은 Silvaco 실행 성공으로 보고하지 않는다. 상태는 준비됨/실행 중/실행 실패/해석 완료/물리 검증 통과로 구분한다. 실제 산출물 없는 그래프와 성능 숫자는 만들지 않는다. 허가된 저장소에 작업을 commit/push하고 로컬 HEAD와 원격 브랜치 SHA 일치를 확인한다. 최종적으로 저장소 링크, 실행 프롬프트, 핵심 출처, 구조/모델/목표, 실제 실행 상태와 Id–Vg 결과 또는 남은 외부 장애를 구체적으로 보고한다.
