# agent 설정 저장과 자동 복구

**후속 구성 완료:** [터널 주소 자동 복구](터널주소_자동복구_20261121.md). 아래 초기 구성 당시 남아 있던 주소 소실 문제도 이후 비공개 GitHub 접점과 서명된 주소 발견으로 보완했고, 실제 터널 종료 후 수동 입력 없는 복구를 확인했다.

2026-11-21 사용자 요청으로 기존 인증 agent를 통해 설치했다. 추가 수동 등록 없이 새 agent 전환과 실제 감독 프로세스 종료·복구 시험을 수행했다.

- 원격 설정: `~/.local/share/gaa_persistent_agent/config.json`, 소유자만 읽고 쓰는0600, 디렉터리0700. URL·토큰·공개CA·기한없음 설정을 저장한다. 토큰은 인자/로그/Git에 넣지 않는다.
- agent 연결 실패: 같은 HTTPS 주소로 계속 재시도한다. 시작 시 연결 실패나 agent 비정상 종료는 감독 프로세스가10초 후 재시작한다.
- 감독 프로세스 종료: 기존 사용자 crontab을 보존하고 GAA 전용1분 watchdog 항목을 추가했다. 중복 기동은 flock으로 방지한다. 서버 재부팅 뒤 crond가 사용자 작업을 실행하면 같은 항목이 다시 기동한다. 실제 서버 재부팅 시험은 하지 않았다.
- 중복 계산 방지: 이미 존재하는 실행 ID를 다시 실행하지 않는다. pending_result.zip이 있으면 결과 전송만 재시도한다. 기존 TCAD 실행/구조/덱은 변경하지 않았다.
- 명시적 중지: 원격 `~/.local/share/gaa_persistent_agent/stop.request`가 있으면 cron도 다시 기동하지 않는다. 파일 삭제 후 다음 cron 실행에 재개한다. `/control`의 명시적 agent 중지는 새 감독 프로세스가 이 중지 파일로 기록한다.

실제 시험: supervisor42825/agent42928을 대상으로 우리 감독 프로세스만 종료했다. 약53초 뒤 cron이 supervisor43681/agent43682를 시작했다. 설정0600·소유권·실제명령행·프로세스 존재·원격 파일왕복을 확인했다. 자동화33개 시험도 통과했다. 증거: [agent 자동복구 검증](../검증/agent_자동복구_20261121.json).

한계: 같은 주소에서의 통신 장애와 원격 agent/감독 프로세스 종료를 복구한다. 임시 Cloudflare 주소가 소실되거나 Windows 중계PC가 꺼진 경우 새 주소를 자동 발견하는 고정 접점은 아직 없다. Windows 중계의 부팅 서비스는 이번 Linux agent 설정에 포함하지 않았다. 주소가 바뀌면 설정 갱신 경로 또는 고정 터널이 여전히 필요하다. 인증 검증을 끄거나 외부에 토큰을 공개해 이를 우회하지 않는다.
