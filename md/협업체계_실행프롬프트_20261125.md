**후속 구조 변경:** 같은 날 사용자의 추가 지시에 따라 팀원 이름 폴더를 최상위로 옮겼다. 현재 개인 공간은 `이름/문헌/`, 실험 경로는 `이름/연구/주제/실행ID/`다. 아래 `연구/팀원실험/` 표기는 최초 계획의 기록이며 현재 작업은 [팀원 공간](협업/팀원공간.md)을 따른다.

## 사용자 목적과 확인된 선택

GAA GitHub는 팀원이 각자 수행한 TCAD 실험의 입력·결과·검증을 공유하는 저장소다. 초보자도 VS Code와 AI를 이용하거나 AI 없이 결과를 제출할 수 있어야 한다. 사용자는 공개 저장소로 전환하고 지정 팀원에게 쓰기 권한을 주도록 선택했다. 팀원 GitHub 아이디는 질문했으며, 미제공 상태에서는 추측해서 초대하지 않는다.

확인된 팀원 이름: 곽민재, 권도현, 윤석영, 박선우, 진. 사용자는 GitHub 아이디를 나중에 제공한다고 답했다. 이름별 폴더를 준비하되 이름으로 계정을 검색·추정하여 초대하지 않는다.

사전 확인 결과 기존 rendezvous 게시 코드에 private 저장소만 허용하는 조건이 있다. 공개 전환 후 주소 자동 복구가 중단되지 않도록, 고정 스키마의 서명된 주소 문서만 게시하도록 호환 수정하고 인증 거부·서명 검증을 시험한다. 실행 중인 원격 계산은 보존한다. 필요 시 같은 토큰·큐·runtime을 유지한 채 해당 Windows 중계 controller만 백그라운드에서 교체하고 HTTPS·agent 재접속을 확인한다. 계산이나 원격 agent는 재시작하지 않는다.

## 사전 확인과 보존

1. C:/dev/gaa의 AGENTS.md, 현재 브랜치, 미커밋 변경, README, 연구/01_GAA_IdVg/md/설계와목표.md를 읽는다. 현재 main의 기존 작업을 보존한다.
2. 다른 저장소·사용자의 작업·실행 중인 TCAD·원격 agent를 중지하거나 화면/입력 장치를 조작하지 않는다. 중계 호환 교체는 위에 정한 범위에서만 수행한다.
3. 실제 실행 덱·로그·구조와 자동화가 참조하는 경로는 유지한다. 재구성은 문서 색인과 새 팀 실험 공간을 중심으로 수행한다. 문서는 md/, Python은 python/, 덱은 tcad/, 검증은 검증/, 그림은 그림/에 둔다. 연구 하위에도 같은 구조를 사용한다.
4. GitHub 관리 권한·공개 범위·협업자·브랜치 보호를 확인한다. 공개 전환 전 모든 원격 브랜치와 Git 이력의 자격 증명 노출 및 기존 자동화의 private 전제를 점검한다. 해결되지 않은 실제 위험은 공개 전환 전에 설명하고 필요한 선택만 질문한다.

## 구현

1. README를 팀 협업 입구로 정리하고 기존 연구·과거 운영 기록으로 가는 링크를 보존한다.
2. md/협업/에 시작 안내, VS Code+AI 절차와 복사용 프롬프트, AI 없는 VS Code/터미널/GitHub 웹 절차, 실험 제출 규칙과 관리자 접근 설정 안내를 작성한다. Git·GitHub, clone·branch·stage·commit·push·pull·PR을 초보자 말로 구분한다.
3. 팀원/주제/실행 ID별 독립 폴더, 사전 계획, 실행 정보, 검증·요약·그림·대용량 원본 해시/위치 기록 양식을 제공한다. 성공·실패·미실행과 수치/물리 검증을 구분한다. 공용 색인의 동시 편집을 줄이는 구조를 사용한다.
4. 필요하면 표준 라이브러리 Python으로 기존 폴더를 덮어쓰지 않는 실험 폴더 생성 도구를 제공한다. GitHub Issue/PR 양식과 main 검토 절차를 마련한다. GitHub 자동 검사는 파일 구조에 한정하며 TCAD/물리 통과로 표현하지 않는다.
5. 공개 전환과 지정된 협업자 권한을 API로 변경한다. 연결 도구에 설정 기능이 없으면 기존 Git 인증을 메모리에서만 사용하는 비대화형 API를 이용한다. 비밀값을 파일·터미널·문서에 출력하지 않는다. 팀원 아이디가 없으면 공개 접근과 초대 대기를 구분해서 기록한다.
6. 팀원은 작업 브랜치→검토 요청(PR)→main 반영을 기본으로 한다. 실행 ID 원본은 덮어쓰지 않는다. 실험 간 조건·단위·메시·모델 차이를 기록한다. 라이선스·서버 자격 증명은 각자 별도로 준비하며 GitHub 접근이 TCAD 서버 접근을 제공한다고 설명하지 않는다.
7. 최신 GitHub/VS Code 공식 문서를 확인해 안내 자료에 출처와 확인일을 적는다.

## 검증과 완료 기준

- 문서의 내부 링크·폴더 구조·예제 명령을 확인하고 필요한 로컬 도구 검증을 실행한다. 정적 검증은 실제 Silvaco 실행과 명확히 구별한다.
- 기존 추적 자료의 내용 해시와 실행 경로가 보존되었는지 확인한다. 새 결과나 측정값은 만들지 않는다.
- 변경 내용을 검토한 뒤 이 작업 파일만 main에 커밋·push한다. 기존 미커밋 변경은 포함하지 않는다. 로컬 HEAD와 원격 main SHA 일치 여부를 확인한다.
- API로 최종 공개 범위·브랜치 규칙·협업자/초대 상태를 다시 읽어 확인한다. 파일 작성, 로컬 커밋, 원격 반영, 팀원 초대 수락을 각각 구분해서 보고한다.
- 질문이 남아도 독립적인 문서·폴더 정리는 끝낸다. 실제로 미완료인 접근 설정은 완료라고 표시하지 않는다.
