## 실행 구조와 시간

원격 `gaa_autonomous_20261117T064609Z`는 기존 agent의 인증·해시 패키지 경로로 제출했다. `night_entry.py`가 새 agent와 독립 `night_supervisor.py`를 시작한다. 기존 연구나 실행을 중단하지 않는다.

- 새 transport 만료: **2026-11-18 15:44 KST**. 11/17 17시~11/18 09시 구간 포함. `night_runtime.json`이 실제 runtime을 가리킨다.
- 독립 HTTPS 터널 두 개가 같은 loopback 전용 인증 서버에 연결된다. agent 요청은 주 경로 실패 시 보조 경로로 전환한다. 인증과 TLS 검증은 그대로다.
- 결과 전송 실패 시 ZIP을 원격 `pending_result.zip`에 보관하고 같은 결과를 재전송한다. 전송 때문에 TCAD를 재실행하지 않는다.
- 원격 계산과 유한 후속 계획은 transport 만료와 무관한 독립 세션이다. 덱별·전체 계산 시간 제한은 설정하지 않는다.
- 로컬 `night_watch.py`가 10분마다 원래34개 작업과 새 복구 작업의 로그·수치·상태를 받아 SHA 검증하고 `.local/night_latest.json`을 만든다. 모델 호출은 0회다.
- 기존34개 작업의 최신 실행 중 개수가 2개 이하일 때 복구계획을 시작한다. 새 계획은 동시1개, 2덱 한정이다. 기존 실행은 다시 제출하지 않는다.

## 이번 자동 수정과 분석

실패했던 `wf4p55_fine`, `wf4p6_fine`의 high sweep은 실제 Vds가 각각 약0.490V, 0.341V였다. 목표0.6V를 채우지 못한 결과는 정상 종료여도 유효한 high 결과로 쓰지 않는다.

복구 덱은 기존 fine 물리·구조·메시·게이트 스윕·목표를 유지하고 **드레인 ramp 간격만0.01→0.002V**로 줄인다. `연구/01_GAA_IdVg/tcad/gaa_autonomous_20261117T064609Z/`에 새 덱과 해시 계획을 보관한다. 기존 full 결과와 메시 비교도 수행한다. ATLAS 정상 종료, native bias grid, 출력, KCL, 단조성 검사를 거친다. 메시 비교와 공학 목표/물리 검증의 합격 여부는 별도로 보고한다.

근거: [Silvaco ATLAS 제조사 매뉴얼(대학 보관본)](https://cfd.rit.edu/products/manuals/Silvaco/atlas_users.pdf)은 첫 비영점 바이어스와 초기 추정의 어려움, TRAP에 의한 step 축소를 설명한다. 작은 ramp는 이 실패에 대한 수치 실험이며 성공을 보장하는 물리적 결론이 아니다. 설치버전의 실제 로그로 확인한다.

식별 가능한 라이선스 실패는 기존 `run_case.py`에 따라 최대2회 추가 시도하고 매번 새 attempt에 저장한다. 미분류 오류·메모리 부족·물리 모델 변경은 무작정 반복하지 않는다. 새 연구자료를 임의 코드로 내려받아 실행하지 않는다.

## 확인 명령과 재개

아래 명령은 화면이나 클립보드를 쓰지 않는다.

```powershell
cd C:\dev\gaa
Get-Content .local/runtime.json
Get-Content .local/night_latest.json
Get-Content .local/night_watch.json
py -3.11 python/automation/control.py status
```

원격 원본: `~/gaa_tcad_runs/gaa_overnight_20261116T080149Z/durable/`, 복구는 `~/gaa_tcad_runs/gaa_autonomous_20261117T064609Z/durable/`. 로컬 원본 회수는 `.local/collected/<snapshot>/`, 짧은 인계 증거는 `연구/01_GAA_IdVg/검증/무인운용_20261117.json`.

로컬 감시가 종료됐다면 먼저 `night_watch_pid.json` PID의 command line과 실제 존재 여부, `night_watch.console`, deadline, 이미 제출된 queue/receipt를 확인한다. 기존 pending queue를 덮어쓰거나 같은 스냅샷을 재실행하지 않는다. 새 모델 세션은 보관된 결과를 읽고 필요할 때만 로그 일부를 검토한다.

## 보장 범위와 남은 한계

[Cloudflare 공식 문서](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)는 Quick Tunnel의 uptime을 보장하지 않는다. 이중화는 단일 경로 장애를 줄이지만 두 경로·학교망·PC 전원·서버 장애에 대한 무중단 보장은 아니다. 두 URL이 모두 소실되면 원격에 전달한 계산과 검증은 계속되지만 다음 코드 전송은 고정 접점이 복구될 때까지 불가능하다. 영구 연결은 학교가 허용하는 고정 VPN/SSH 또는 계정·도메인이 연결된 관리형 tunnel 같은 고정 접점이 필요하며 아직 구성하지 않았다.

무인 계획은 미리 정의한 두 수치 수정안과 검증을 자동 수행한다. Python이 모델을 대신해 밤새 새로운 논문을 해석하거나 임의의 과학적 모델을 설계하지 않는다. 일반적인 자율 리서치·코드 수정까지 무제한 수행하려면 별도의 인증된 모델/API 실행 환경, 비용 한도와 고정 통신 경로가 필요하다. 현재는 문헌을 검토해 수정안을 사전 패키지에 포함하고, 미분류 결과를 새 세션으로 인계하는 방식이다.
